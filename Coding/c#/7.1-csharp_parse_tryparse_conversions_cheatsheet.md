# C# Cheatsheet: Parse, TryParse, ReadLine, and Data Type Conversions
_A simple, detailed, overexplained guide_

---

## What this cheatsheet is about

This guide ties together several beginner C# ideas that constantly show up together:

- `Console.ReadLine()`
- strings
- numeric input
- `Parse()`
- `TryParse()`
- `.ToString()`
- casting
- `Convert`
- converting between common data types

These ideas matter because a huge amount of beginner programming looks like this:

1. get text input
2. convert the text into the type you actually need
3. use the converted value in math, conditions, loops, or functions

---

# Part 1: The giant rule

## `Console.ReadLine()` always gives you a `string`

This is the most important rule in this whole topic.

Example:

```csharp
string text = Console.ReadLine();
```

Even if the user types:

```text
25
```

C# still sees it as:

```csharp
"25"
```

That is text, not a number.

So if you want to use it as an `int`, `double`, or another numeric type, you must convert it.

---

# Part 2: Why conversion is needed

This does **not** work:

```csharp
int x = Console.ReadLine();
```

Why?

Because `Console.ReadLine()` returns a `string`, and C# will not automatically turn that string into an `int`.

So the normal pattern is:

1. read text
2. convert text
3. use the converted value

---

# Part 3: `Parse()`

`Parse()` converts text into another type.

## Example: string to int

```csharp
string text = "42";
int number = int.Parse(text);
```

Now `number` is a real `int`.

---

# Part 4: `Console.ReadLine()` with `Parse()`

```csharp
Console.Write("Enter a number: ");
int number = int.Parse(Console.ReadLine());

Console.WriteLine("You typed: " + number);
```

This is a very common beginner pattern.

### What happens

- `ReadLine()` gets text
- `int.Parse(...)` converts the text into an integer
- now you can use it like a number

---

# Part 5: The danger of `Parse()`

`Parse()` crashes if the text is invalid.

Example:

```csharp
int number = int.Parse("hello");
```

That fails because `"hello"` is not a valid integer.

So `Parse()` is okay when you are sure the text is valid, but risky for user input.

---

# Part 6: `TryParse()`

`TryParse()` is the safer version.

## Example

```csharp
string text = "42";

if (int.TryParse(text, out int number))
{
    Console.WriteLine(number);
}
else
{
    Console.WriteLine("That was not a valid integer.");
}
```

### What happens

- if conversion works, it returns `true`
- if conversion fails, it returns `false`
- no crash happens

That is why `TryParse()` is usually better for user input.

---

# Part 7: `Console.ReadLine()` with `TryParse()`

```csharp
Console.Write("Enter a number: ");
string text = Console.ReadLine();

if (int.TryParse(text, out int number))
{
    Console.WriteLine("Valid number: " + number);
}
else
{
    Console.WriteLine("That was not a valid integer.");
}
```

This is the standard safe pattern.

---

# Part 8: Do you need to parse every time?

Important nuance:

## You must convert every time you want to turn new text into a number

That means yes, whenever you get fresh numeric user input from `ReadLine()`, there must be some conversion step.

But you do **not** repeatedly parse the same value after it is already converted.

Example:

```csharp
Console.Write("Enter a number: ");
int num = int.Parse(Console.ReadLine());

Console.WriteLine(num);
Console.WriteLine(num + 5);
Console.WriteLine(num * 2);
```

Here:

- parse happens once
- after that, `num` is already an `int`
- you just use it normally

So the pattern is:

- input comes in as text
- parse once
- use many times

---

# Part 9: `Parse()` vs `TryParse()`

## Use `Parse()` when
you are sure the text is valid.

Example:

```csharp
string text = "42";
int x = int.Parse(text);
```

## Use `TryParse()` when
the text may be bad or uncertain.

Examples:
- user input
- file input
- internet input
- any outside source you do not fully trust

Example:

```csharp
if (int.TryParse(text, out int x))
{
    Console.WriteLine(x);
}
```

# Part 10: Best beginner memory hook

- `ReadLine()` = text
- `Parse()` = convert text
- `TryParse()` = safely convert text
- `.ToString()` = convert other things into text

# Part 21: Number to number conversions

Sometimes you want to convert one numeric type into another.

## int to double

```csharp
int x = 5;
double y = x;
```

This is automatic because `double` can hold a wider range.

## int to float

```csharp
int x = 10;
float y = x;
```

Also usually automatic.

## double to int

```csharp
double x = 5.9;
int y = (int)x;
```

Result:

```text
5
```

This cuts off the decimal part.
It does not round.

## float to int

```csharp
float x = 9.8f;
int y = (int)x;
```

Again, the decimal part is chopped off.

## long to int

```csharp
long big = 100;
int small = (int)big;
```

This may lose data if the `long` is too large.

## int to byte

```csharp
int x = 100;
byte b = (byte)x;
```

Needs a cast because `byte` is much smaller.

# Part 24: Cast vs Convert

This difference matters:

```csharp
Console.WriteLine((int)5.9);
Console.WriteLine(Convert.ToInt32(5.9));
```

Output:

```text
5
6
```

Why?

- `(int)5.9` truncates
- `Convert.ToInt32(5.9)` rounds

That is a very important difference.

# Part 25: Parse vs TryParse vs Convert

## `Parse`
```csharp
int x = int.Parse("42");
```

- good when text is valid
- crashes on invalid input

## `TryParse`
```csharp
if (int.TryParse("42", out int x))
{
    Console.WriteLine(x);
}
```

- safest for user input
- does not crash

## `Convert`
```csharp
int x = Convert.ToInt32("42");
```

- useful general conversion tool
- common in many codebases

Best beginner rule:

- use `TryParse` for user input
- use `Parse` when you are sure the text is valid
- use casts or `Convert` for non-string conversions

# Part 28: Safe repeated input loop

A very common real pattern is:

> keep asking until the user enters a valid number

```csharp
using System;

class Program
{
    static void Main()
    {
        int number;

        while (true)
        {
            Console.Write("Enter an integer: ");
            string text = Console.ReadLine();

            if (int.TryParse(text, out number))
            {
                break;
            }

            Console.WriteLine("That was not a valid integer. Try again.");
        }

        Console.WriteLine("You entered: " + number);
    }
}
```

This is one of the most useful beginner patterns in input handling.

# Part 29: Common beginner mistakes

## Mistake 1: Forgetting `ReadLine()` gives text

Wrong mental model:

> "The user typed 25, so I already have an int."

No.
You have the string `"25"` until you convert it.

## Mistake 2: Using `Parse()` on unsafe user input

```csharp
int x = int.Parse(Console.ReadLine());
```

This can crash if the user types junk.

Use `TryParse()` when input is uncertain.

## Mistake 3: Re-parsing the same value again and again

Bad idea:

```csharp
string text = Console.ReadLine();
Console.WriteLine(int.Parse(text));
Console.WriteLine(int.Parse(text) + 5);
Console.WriteLine(int.Parse(text) * 2);
```

Better:

```csharp
string text = Console.ReadLine();
int num = int.Parse(text);

Console.WriteLine(num);
Console.WriteLine(num + 5);
Console.WriteLine(num * 2);
```

Parse once, use many times.

## Mistake 4: Confusing char and string

```csharp
char a = 'A';
string b = "A";
```

These are different.

- `'A'` = one character
- `"A"` = string containing one character

## Mistake 5: Forgetting casts can lose information

```csharp
double x = 5.9;
int y = (int)x;
```

You lose the `.9`.

# Part 31: Full demo program

```csharp
using System;

class Program
{
    static int DoubleIt(int x)
    {
        return x * 2;
    }

    static void Main()
    {
        Console.WriteLine("=== PARSE EXAMPLES ===");
        string intText = "42";
        string doubleText = "3.14";
        string boolText = "true";
        string charText = "Z";

        int myInt = int.Parse(intText);
        double myDouble = double.Parse(doubleText);
        bool myBool = bool.Parse(boolText);
        char myChar = char.Parse(charText);

        Console.WriteLine(myInt);
        Console.WriteLine(myDouble);
        Console.WriteLine(myBool);
        Console.WriteLine(myChar);

        Console.WriteLine();
        Console.WriteLine("=== TOSTRING EXAMPLES ===");
        string backToText1 = myInt.ToString();
        string backToText2 = myDouble.ToString();
        string backToText3 = myBool.ToString();
        string backToText4 = myChar.ToString();

        Console.WriteLine(backToText1);
        Console.WriteLine(backToText2);
        Console.WriteLine(backToText3);
        Console.WriteLine(backToText4);

        Console.WriteLine();
        Console.WriteLine("=== CAST VS CONVERT ===");
        double decimalNumber = 9.8;
        int cutDown = (int)decimalNumber;
        int rounded = Convert.ToInt32(decimalNumber);

        Console.WriteLine(cutDown);
        Console.WriteLine(rounded);

        Console.WriteLine();
        Console.WriteLine("=== TRY PARSE WITH USER INPUT ===");
        Console.Write("Enter an integer: ");
        string userText = Console.ReadLine();

        if (int.TryParse(userText, out int userNumber))
        {
            Console.WriteLine("Valid integer: " + userNumber);
            Console.WriteLine("DoubleIt result: " + DoubleIt(userNumber));
        }
        else
        {
            Console.WriteLine("That was not a valid integer.");
        }
    }
}
```
